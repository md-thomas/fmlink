OpenWave - An Open Digital Radio Stack

OpenWave is an open, modern digital radio framework designed for
high-performance wireless communications. It provides a flexible,
modular stack for building interoperable digital radio systems,
with a focus on maximizing data throughput while minimizing occupied
spectral bandwidth.

At its core, OpenWave is a link-layer/framing protocol (header, CRC,
sequencing, ACK/retry, fragmentation, FEC) designed to run over a
pluggable PHY rather than being tied to one modulation. Waveform Mode ID
in the header selects a modulation/symbol-rate/FEC combination (see
openwave_link.py's WAVEFORM_MODES); BPSK, QPSK, and 16-QAM are supported
today.

Built for experimentation, research, and real-world deployment, 
OpenWave aims to provide an open foundation for next-generation 
Amateur Radio and SDR applications.

Channel Bandwidth:
VHF: 	Modes 0-3 within 15 kHz channels
UHF:  	Modes 0-4 within 25 kHz channels
(Direct RF modulation, e.g. an SDR. Through a radio's audio port the
audio passband is the limit instead - see Audio PHY below.)

Modem Chain:
	Application Data
    		|
    Packet Builder (Header + Payload + CRC32)
            |
    FEC Encoder
    		|
    Interleaver
    		|
    PHY Modulator (pluggable)
    		|
    RRC Filter
    		|
            RF

Physical Layer (PHY)
    Modulation: 		        Pluggable per Waveform Mode ID - BPSK, QPSK, and
    				            16-QAM supported today (see openwave_link.py's
    				            WAVEFORM_MODES and modulate.py/demodulate.py)
    Symbol Rates: 	            600, 1200, 2400, 4800, 9600 symbols/sec
    Raw Bit Rates: 	            Depends on the mode's modulation - see
    				            Waveform Modes table below (600 bps - 38.4 kbps
    				            across the modes defined today)
    Filtering:  		        Root Raised Cosine
    Roll-off: 		            0.35
    Synchronization:            The receiver locates each frame by correlating
                                against the known preamble + sync word (the
                                "marker"). Over IQ this is a bit-level match
                                that tolerates up to 15% wrong marker bits.
                                On the audio PHY it is a sample-level
                                correlation that also yields symbol timing,
                                carrier phase and signal level; the frame
                                is then decoded at that position.
                                Carrier and timing drift are tracked on the
                                audio PHY only (see Audio PHY). The IQ PHY
                                does no carrier recovery yet.
    Forward Error Correction:	Convolutional code, rate 1/N, constraint
    				            length K, hard-decision Viterbi at the
    				            receiver (presets: openwave_fec.py's PRESETS).
    				            The lead pad, preamble and sync word are sent
    				            uncoded - the receiver finds them by
    				            correlation, which needs a fixed known
    				            pattern. The rest of the frame is two
    				            independent blocks, each encoded separately:
    				                1. the 20-byte header
    				                2. payload + CRC32
    				            Each block is flushed with K-1 zero tail bits,
    				            then interleaved (below), then zero-padded to
    				            a whole byte. The end pad stays uncoded.
    Interleaver:		        Per FEC block, over its N coded bits (tail
    				            included, padding excluded); bits are numbered
    				            0..N-1 in encoder output order, MSB-first within
    				            each byte on the wire. Transmitted bit j is
    				            coded bit (j * s) mod N.
    				            s is found from s0 = round(N * (sqrt(5) - 1) / 2):
    				            for d = 0, 1, 2, ..., try s0 + d, then s0 - d,
    				            and take the first value with 0 < s < N and
    				            gcd(s, N) = 1. (N <= 1: no reordering.)
    				            Consecutive channel bits come from coded bits
    				            far apart, so a fade's or click's burst of
    				            errors reaches the Viterbi decoder as scattered,
    				            correctable errors.

Audio PHY (a radio's audio port, e.g. a VHF/UHF FM transceiver):
    Interface:                  Real audio, 48000 samples/sec. 16-bit signed
                                little-endian mono PCM where samples are
                                exchanged (e.g. the ota_sim FM channel).
    Pulse shaping:              RRC as above (roll-off 0.35, 11-symbol
                                span), 48000 / symbol rate samples per symbol
                                - every Waveform Mode's rate divides 48000.
    Carrier:                    The complex baseband signal b(t) is sent as
                                Re{ b(t) * exp(j*2*pi*fc*t) }, scaled to a
                                peak of 0.7 of full scale. fc depends on the
                                audio connection, and both ends must use the
                                same one:
                                  mic  (microphone/speaker path, ~300-3000 Hz,
                                       pre/de-emphasis): max 2400 sym/s -
                                       Modes 0-3. fc = 1650 Hz for 600 and
                                       1200 sym/s, fc = 2000 Hz for 2400
                                       sym/s (Mode 3; measured on air
                                       through two HTs, 2026-10-07)
                                  data (6-pin data port, flat to ~5 kHz):
                                       fc = 2000 Hz, max 2400 sym/s - Modes 0-3
                                Modes 4-5 don't fit an FM radio's audio
                                passband (nothing above ~4 kHz gets
                                through an HT's mic/speaker path).
    Burst:                      Lead-in silence (default 250 ms; it must
                                exceed the transmitter's key-up time plus
                                the far receiver's squelch opening time),
                                then the frame with NO lead/end pad and a
                                16-byte preamble (see Link layer), then
                                20 ms of silence for the filter tail. One
                                frame per burst.
    Receiver (informative):     Correlate against the marker for timing,
                                phase and level; equalize the radios'
                                audio response with a short FIR fitted to
                                the known marker symbols (least squares,
                                taps every half symbol); decode at that
                                position; track sound-card clock drift
                                (which shifts carrier phase and symbol
                                timing together) with a decision-directed
                                PLL. See openwave_audio.py.

Link layer:
    Frame format version:       2 (since 2026-10). v1 had a 32-byte header,
                                8-byte ASCII IDs and a 32-byte preamble on
                                every PHY; v1 and v2 stations can't decode
                                each other's frames.
    Frame:                      Lead Pad + Preamble + Sync Word + Header +
                                Payload + CRC32 + End Pad
    Lead Pad / End Pad:         Zero bytes before the preamble and after the
                                CRC. 24 each on the IQ PHY, which needs
                                them for its fixed-timing matched filter;
                                none on the audio PHY, whose lead-in silence
                                and filter tails do the same job. Receivers
                                must not depend on them.
    Preamble:	                LFSR pseudo-noise sequence (seed 1, 9-bit register,
	                            taps 1/2/5/9 - see openwave_link.py's _lfsr_pn_bits/PREAMBLE):
	                              IQ PHY:    32 bytes
	                              Audio PHY: the first 16 bytes of the same
	                                         sequence (its receiver correlates
	                                         against samples, not bits; 16
	                                         bytes delivered the same as 32
	                                         through the FM model, 8 and below
	                                         did not)
	                            A PN sequence rather than a repeating pattern (e.g.
	                            55 55...) because its autocorrelation has a sharp,
	                            unambiguous peak (worst sidelobe ~9% of peak) vs. a
	                            repeating pattern's ~99% sidelobes at every
	                            symbol-period offset.
    
    Sync Word: 	                4 bytes (CCDS sync word) 0x1ACFFC1D (for correlation)	
    Payload: 	                Variable (maximum 1024 bytes)
    CRC32:	                    4 bytes, over header + payload
    Header: 	                Total 20 bytes
        Version / Packet Type:	1 byte - version in the high 4 bits (2),
                                packet type in the low 4 bits
        Waveform Mode ID:	    1 byte
        Flags: 			        1 byte
        Sequence Number:	    2 bytes
        Source ID:		        6 bytes (packed callsign, see below)
        Destination ID: 	    6 bytes (packed callsign; "ALL" = broadcast)
        Payload Length:	        2 bytes
        Fragment Index:	        1 byte
        All multi-byte fields are big-endian. There are no reserved bytes:
        room to grow is Flags bit 5 (header extension, below), Flags bits
        6-7, packet types 5-15 and versions 3-15.

        Packet Types:
            0x01 = Data
            0x02 = ACK
            0x03 = Beacon
            0x04 = Control
            0x05 = AX.25 (the payload is one AX.25 frame, for a KISS TNC's
                   host - see below)

        ACK frame:
            Packet Type ACK, Flags bit 1 (ACK Response) set, empty
            payload. Its Sequence Number is the Sequence Number of the
            frame being acknowledged; each fragment of a fragmented
            message is acknowledged separately.

        Selective ACK (burst batching; only between stations that both
        offered CAP_BATCH in negotiation - see Control frame payloads):
            Packet Type ACK, Flags bit 1 set, with a payload:
                [count: 1 byte, 1-64][bitmap: ceil(count / 8) bytes]
            Its Sequence Number is the first fragment's Sequence Number
            (seq - fragment index) of the message being acknowledged.
            Bit i of the bitmap (byte i // 8, LSB first) is set if the
            fragment with Fragment Index i has been received. count is
            the number of fragments the bitmap covers (the message's
            total once its last fragment has arrived). An ACK with an
            empty payload is always a plain ACK.
            A batching sender sends several fragments in one
            transmission with only the last one's ACK Requested flag
            set, then resends only the fragments a selective ACK reports
            missing. The receiver sends a selective ACK when a fragment
            with ACK Requested arrives, and also once the batch has gone
            quiet without one (its last fragment was lost); it
            reassembles fragments in any order and delivers a message
            only when fragments 0 to the last (the one without More
            Fragments) are all present.

        AX.25 frame (packet type 0x05):
            The payload is one AX.25 frame as KISS carries it (addresses,
            control, PID, info; no HDLC flags, no AX.25 FCS - the frame's
            CRC32 protects it). Sent by openwave_tnc.py, the KISS TNC, for
            packet software running on top (e.g. the Linux kernel AX.25
            stack). AX.25 does its own addressing, connections and
            retries, so these frames never request an OpenWave ACK and are
            never fragmented. A receiver passes every one to its KISS host
            regardless of Destination ID. Source/Destination ID carry the
            AX.25 source/destination callsigns when they can be packed, for
            information only.

        Control frame payloads (first byte = op):
            0x01 MODE_REQUEST  [op]
                 Probe sent by the station starting negotiation, so the
                 peer has something to measure and reply to.
            0x02 MODE_GRANT    [op][SNR: float32, big-endian][mode: 1 byte]
                               [FEC preset ID: 1 byte][capabilities: 1 byte]
                 Reply to a MODE_REQUEST, with the same Sequence Number.
                 The SNR and mode/preset are the replier's own
                 non-binding opinion; the requester decides from its own
                 measurement of this reply.
            0x03 MODE_SET      [op][mode: 1 byte][FEC preset ID: 1 byte]
                               [capabilities: 1 byte]
                 The requester's decision. Both stations use this
                 mode/FEC in both directions from then on.
            Capabilities (optional trailing byte of MODE_GRANT and
            MODE_SET; absent = 0, and receivers ignore trailing bytes,
            so stations without it still interoperate):
                 bit 0  CAP_BATCH - burst batching with selective ACKs.
                        Used only when both stations set it.
            0x04 MODE_SET_ACK  [op]
                 Confirms a MODE_SET, with the same Sequence Number.
            0x05 PING          [op]
            0x06 PONG          [op]
                 Round-trip probe and its reply (same Sequence Number),
                 sent at the currently active mode.
            FEC preset IDs (never renumbered; new presets only append):
                1 r1_2_k3   2 r1_2_k7   3 r1_2_k9
                4 r1_3_k3   5 r1_3_k7   6 r1_3_k9
                7 r1_4_k3   8 r1_4_k7   9 r1_4_k9
               10 r1_5_k7  11 r1_5_k9
               12 r1_6_k7  13 r1_6_k9
            (names are openwave_fec.py's PRESETS keys).
            MODE_REQUEST/GRANT/SET/SET_ACK are sent on a fixed
            control channel both ends know in advance: Mode 0 with FEC
            "r1_2_k9" (ota_station.py's CONTROL_MODE_ID/CONTROL_FEC_PRESET).
            How the requester picks a mode from its measurement is local
            policy, not part of the wire format (ota_station.py uses
            openwave_link.py's MODE_SNR_TABLE, or FADING_MODE_SNR_TABLE
            when the probe shows fading).

        Waveform Modes: (modulation/rate/FEC bundle - see openwave_link.py's
        WAVEFORM_MODES, the authoritative table; currently a documentation/
        lookup contract, not yet wired into the CLI modulation/FEC flags)
            Mode 0: 	600 symbols/sec, bpsk,  600 bps raw
            Mode 1: 	1200 symbols/sec, bpsk,  1200 bps raw
            Mode 2: 	1200 symbols/sec, qpsk,  2400 bps raw
            Mode 3: 	2400 symbols/sec, qpsk,  4800 bps raw
            Mode 4: 	4800 symbols/sec, qpsk,  9600 bps raw
            Mode 5: 	9600 symbols/sec, 16qam, 38400 bps raw

	    Flags: 1 byte 
            Bit 0: 	ACK Requested 
                0 = No acknowledgment required 
                1 = Sender requires ACK 
            
            Bit 1: 	ACK Response 
                0 = Normal frame 
                1 = This frame is an ACK response 
            
            Bit 2: 	Fragmented Frame 
                0 = Complete payload 
                1 = Payload is part of a fragmented message 

            Bit 3: 	More Fragments 
                0 = Last fragment 
                1 = More fragments follow 

            Bit 4: Priority 
                0 = Normal priority 
                1 = High priority 

            Bit 5: Header Extension
                0 = The payload is all application data
                1 = The payload starts with a header-extension block

            Bit 6: Reserved
            Bit 7: Reserved

        Header extension (Flags bit 5):
            [block length N: 1 byte][N bytes of entries][application payload...]
            entry = [type: 1 byte][length L: 1 byte][L bytes of value]
            Payload Length counts the whole payload, block included. A
            receiver skips entry types it doesn't recognize (using their
            length), so it can still read the application payload; a
            malformed block makes the frame unusable. In a fragmented
            message each fragment carries its own block, removed before
            reassembly. No entry types are defined yet.

        Fragment Index: 1 byte
            Position of this frame within its fragmented-message run
            (0-255). Only meaningful when the Fragmented flag (Bit 2) is
            set - ignored otherwise.

            0 = this frame authoritatively starts a NEW fragmented-message
                run (a receiver may safely (re)start reassembly here,
                abandoning any run already in progress).
            1, 2, 3... = a continuation of an in-progress run; a receiver
                must only accept it if it actually matches an in-progress
                run's expected Fragment Index, Sequence Number, and Source
                ID - otherwise the frame must be discarded, NOT treated as
                the start of a new run. (Without this rule, a continuation
                fragment left over from an abandoned/overflowed run could
                be silently misread as the start of a new message, letting
                a truncated tail reassemble into something that looks like
                a complete, valid message.)


        Source ID / Destination ID Encoding (packed callsign):
            Up to 9 characters from a 40-symbol alphabet:
                index 0 = end/padding, 1-26 = A-Z, 27-36 = 0-9,
                37 = '/', 38 = '-', 39 = '.'
            Lowercase is folded to uppercase; nothing else is allowed.
            Left-align, pad to 9 characters with index 0, and send
            c0*40^8 + c1*40^7 + ... + c8 as a 48-bit big-endian integer
            (40^9 < 2^48, so it always fits). Decode the base-40 digits
            most-significant first and stop at the first 0.

    Examples:
        "K0MDT"      -> 45 A3 24 2B 40 00
        "W1AW"       -> 8D 44 D5 05 80 00
        "ALL"        -> 07 CB 16 30 00 00
        "K0MDT-7"    -> 45 A3 24 51 30 80
        "W1AW/P"     -> 8D 44 DA BA 70 00
        "VE3XYZ/MM"  -> 83 FD 44 BE DD 55
        "BROADCAST1" -> not valid (more than 9 characters)


    Example (IQ PHY, without the lead/end pad):
        80 7D 33 D8 A1 52 4E 11 	<- Preamble (32 bytes,
        1E 42 5E FB 93 7E 20 21 	   LFSR pseudo-noise
        D5 1A 78 FD B4 8C C8 B1 	   sequence, shown here
        B8 C3 2D 60 98 18 9F CB 	   across 4 lines; the audio
                                       PHY sends the first 2 lines only)
        1A CF FC 1D 			    <- Sync Word
        21 				            <- Version 2 / Packet Type 1 (Data)
        02 				            <- Waveform Mode ID (Mode 2: 1200 sym/s, qpsk)
        01 				            <- Flags (ACK requested) 
        00 01 				        <- Sequence Number 
        45 A3 24 2B 40 00 	        <- Source ID "K0MDT" 
        07 CB 16 30 00 00 	        <- Destination ID "ALL" 
        00 05 				        <- Payload Length (5 bytes)
        00 				            <- Fragment Index (0 - not fragmented, N/A here)
        48 65 6C 6C 6F 		        <- Payload "Hello"
        F4 97 61 37 			    <- CRC32 (Header + Payload)
