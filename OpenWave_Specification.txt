OpenWave - An Open Digital Radio Stack

OpenWave is an open, modern digital radio framework designed for
high-performance wireless communications. It provides a flexible,
modular stack for building interoperable digital radio systems,
with a focus on maximizing data throughput while minimizing occupied
spectral bandwidth.

At its core, OpenWave is a link-layer/framing protocol (header, CRC,
sequencing, ACK/retry, fragmentation, FEC) designed to run over a
pluggable PHY rather than being tied to one modulation. Waveform Mode ID
in the header selects a modulation/symbol-rate/FEC combination (see
openwave_link.py's WAVEFORM_MODES); BPSK, QPSK, and 16-QAM are supported
today.

Built for experimentation, research, and real-world deployment, 
OpenWave aims to provide an open foundation for next-generation 
Amateur Radio and SDR applications.

Channel Bandwidth:
VHF: 	Modes 0-3 within 15 kHz channels
UHF:  	Modes 0-4 within 25 kHz channels

Modem Chain:
	Application Data
    		|
    Packet Builder (Header + Payload + CRC32)
            |
    FEC Encoder
    		|
    Interleaver
    		|
    PHY Modulator (pluggable)
    		|
    RRC Filter
    		|
            RF

Physical Layer (PHY)
    Modulation: 		    Pluggable per Waveform Mode ID - BPSK, QPSK, and
    				    16-QAM supported today (see openwave_link.py's
    				    WAVEFORM_MODES and modulate.py/demodulate.py)
    Symbol Rates: 	        600, 1200, 2400, 4800, 9600 symbols/sec
    Raw Bit Rates: 	        Depends on the mode's modulation - see
    				    Waveform Modes table below (600 bps - 38.4 kbps
    				    across the modes defined today)
    Filtering:  		    Root Raised Cosine
    Roll-off: 		        0.35
    Synchronization:
    Preamble detection
    Carrier recovery
    Symbol timing recovery
    Forward Error Correction: 	TBD

Link layer

    Preamble:	32 bytes (LFSR pseudo-noise sequence, seed 1, 9-bit register,
		taps 1/2/5/9 - see openwave_link.py's _lfsr_pn_bits/PREAMBLE).
		Chosen over a repeating pattern (e.g. 55 55...) because a PN
		sequence's autocorrelation has a sharp, unambiguous peak
		(worst sidelobe ~9% of peak) vs. a repeating pattern's ~99%
		sidelobes at every symbol-period offset, which made exact
		frame-start detection under noise unreliable.
    
    Sync Word: 	4 bytes (CCDS sync word) 0x1ACFFC1D (for correlation)
	
    Header:	    32 bytes
    
    Payload: 	Variable (maximum 1024 bytes)
    
    CRC32:	    4 bytes

    Header: 	Total 32 bytes
        Version: 		    1 byte
        Packet Type:		1 byte
        Waveform Mode ID:	1 byte
		Flags: 			    1 byte
        Sequence Number:	2 bytes
        Source ID:		    8 bytes
        Destination ID: 	8 bytes
        Payload Length:	    2 bytes
        Fragment Index:	    1 byte
        Reserved:		    7 bytes

        Packet Types:
            0x01 = Data
            0x02 = ACK
            0x03 = Beacon
            0x04 = Control

        Waveform Modes: (modulation/rate/FEC bundle - see openwave_link.py's
        WAVEFORM_MODES, the authoritative table; currently a documentation/
        lookup contract, not yet wired into the CLI modulation/FEC flags)
            Mode 0: 	600 symbols/sec, bpsk,  600 bps raw
            Mode 1: 	1200 symbols/sec, bpsk,  1200 bps raw
            Mode 2: 	1200 symbols/sec, qpsk,  2400 bps raw
            Mode 3: 	2400 symbols/sec, qpsk,  4800 bps raw
            Mode 4: 	4800 symbols/sec, qpsk,  9600 bps raw
            Mode 5: 	9600 symbols/sec, 16qam, 38400 bps raw

	    Flags: 1 byte 
            Bit 0: 	ACK Requested 
                0 = No acknowledgment required 
                1 = Sender requires ACK 
            
            Bit 1: 	ACK Response 
                0 = Normal frame 
                1 = This frame is an ACK response 
            
            Bit 2: 	Fragmented Frame 
                0 = Complete payload 
                1 = Payload is part of a fragmented message 

            Bit 3: 	More Fragments 
                0 = Last fragment 
                1 = More fragments follow 

            Bit 4: Priority 
                0 = Normal priority 
                1 = High priority 

            Bit 5: Reserved
            Bit 6: Reserved
            Bit 7: Reserved

        Fragment Index: 1 byte
            Position of this frame within its fragmented-message run
            (0-255). Only meaningful when the Fragmented flag (Bit 2) is
            set - ignored otherwise.

            0 = this frame authoritatively starts a NEW fragmented-message
                run (a receiver may safely (re)start reassembly here,
                abandoning any run already in progress).
            1, 2, 3... = a continuation of an in-progress run; a receiver
                must only accept it if it actually matches an in-progress
                run's expected Fragment Index, Sequence Number, and Source
                ID - otherwise the frame must be discarded, NOT treated as
                the start of a new run. (Without this rule, a continuation
                fragment left over from an abandoned/overflowed run could
                be silently misread as the start of a new message, letting
                a truncated tail reassemble into something that looks like
                a complete, valid message.)


        Source ID / Destination ID Encoding:
            Format:  	Fixed length 8-byte ASCII field
            Encoding: 	UTF-8/ASCII characters Unused bytes padded with 0x00
            Maximum Length: 8 characters

    Examples:
    "K0MDT"
        ASCII: 4B 30 4D 44 54
        Encoded 8-byte field: 4B 30 4D 44 54 00 00 00
    
    "W1AW"
        ASCII:  57 31 41 57
        Encoded 8-byte field: 57 31 41 57 00 00 00 00
    
    "BROADCAST"
        Not valid (exceeds 8 bytes)


    Example:
        80 7D 33 D8 A1 52 4E 11 	<- Preamble (32 bytes,
        1E 42 5E FB 93 7E 20 21 	   LFSR pseudo-noise
        D5 1A 78 FD B4 8C C8 B1 	   sequence, shown here
        B8 C3 2D 60 98 18 9F CB 	   across 4 lines)
        1A CF FC 1D 			    <- Sync Word
        01 				            <- Version 
        02 				            <- Waveform Mode ID (Mode 2: 1200 sym/s, qpsk)
        01 				            <- Packet Type (Data) 
        01 				            <- Flags (ACK requested) 
        00 01 				        <- Sequence Number 
        4B 30 4D 44 54 00 00 00 	<- Source ID "K0MDT" 
        41 4C 4C 00 00 00 00 00 	<- Destination ID "ALL" 
        00 05 				        <- Payload Length (5 bytes)
        00 				            <- Fragment Index (0 - not fragmented, N/A here)
        00 00 00 00 00 00 00 		<- Reserved
        48 65 6C 6C 6F 		        <- Payload "Hello"
        A7 39 82 F1 			    <- CRC32 (Header + Payload)
